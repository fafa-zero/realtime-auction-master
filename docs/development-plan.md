# 两周开发计划

## 项目定位

本项目按照三份课题文档收敛为“面向直播电商场景的 AI 辅助实时竞拍 MVP”。当前阶段优先保证完整演示闭环：

- 直播竞拍商品展示
- 主播开始、重开和取消竞拍
- 用户实时出价
- Socket.IO 多端同步
- 自动延时和封顶成交
- 成交订单和模拟支付
- AI 商品讲解、竞拍复盘和异常出价提示

## 当前已完成

- 使用 React + TypeScript + Vite 实现前端页面。
- 使用 Node.js + Express + Socket.IO 实现后端服务。
- 使用内存数据保存商品、竞拍、出价和订单。
- 实现 HTTP API 查询竞拍快照、开始竞拍、取消竞拍和模拟支付。
- 实现 Socket.IO 出价、广播、自动延时和竞拍结束事件。
- 实现服务端竞拍状态机和出价规则校验。
- 实现出价请求 `clientRequestId`，降低重复点击导致的重复提交风险。
- 实现服务端时间 `serverTime` 校准倒计时。
- 实现 AI 竞拍助手接口，支持商品讲解词、竞拍复盘和异常出价提示。
- AI 接口支持模型 API 配置；未配置模型时使用本地兜底策略，保证演示稳定。

## 测试清单

- 启动竞拍后状态变为 `ACTIVE`。
- 出价低于最低合法价格时被拒绝。
- 出价超过封顶价时被拒绝。
- 出价等于封顶价时自动成交。
- 倒计时最后阶段出价触发自动延时。
- 最大延时次数达到后不再继续延时。
- 倒计时结束且有出价时生成订单。
- 倒计时结束且无出价时标记流拍。
- 主播取消竞拍后继续出价被拒绝。
- 重复点击出价不会重复写入同一请求。
- 模拟支付后订单状态变为已支付。
- 多个浏览器能够同步看到最高价和竞拍状态。
- AI 商品讲解、竞拍复盘和风险提示接口可用。

## 后续扩展

- 引入 MySQL 或 PostgreSQL 持久化商品、竞拍、出价和订单。
- 引入 Prisma 管理数据模型。
- 引入 Redis 保存竞拍实时状态。
- 使用 Redis Lua 脚本保证高并发出价原子性。
- 使用 Socket.IO Redis Adapter 支持多后端实例广播。
- 增加用户登录、主播后台、竞拍历史和订单列表。
